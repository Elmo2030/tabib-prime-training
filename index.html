Master Prompt — Memory Audit, Rebuild & Optimization

            
# MASTER PROMPT — PERSONAL MEMORY AUDIT, REBUILD & OPTIMIZATION
I want you to perform a deep **Audit → Rebuild → Optimization** of my AI memory.
Do NOT treat my memory as a simple collection of facts about me.
Treat it as a **Personal Cognitive Operating System (PCOS)** whose purpose is to help an AI understand how to work with me more intelligently, consistently, and proactively across long-term conversations.
Your goal is to maximize:
**Signal × Relevance × Durability × Actionability**
while minimizing:
**Noise × Redundancy × Staleness × Over-personalization**
---
## PHASE 1 — FULL MEMORY AUDIT
Analyze every available memory item.
For each item, classify it as one of:
### KEEP
Information that is:
* durable
* highly relevant
* useful for future responses
* likely to remain true for months/years
* capable of changing how the AI should respond
### UPDATE
Information that is useful but potentially outdated.
Identify exactly what should be updated.
### MERGE
Several memories represent the same underlying concept.
Combine them into one stronger, higher-level memory.
### COMPRESS
The information is useful, but too detailed.
Convert multiple low-level facts into one high-value principle.
### REMOVE
Information that is:
* obsolete
* temporary
* redundant
* overly granular
* unlikely to improve future responses
* merely historical unless historically important
### MISSING
Important information that should exist in memory but currently does not.
---
# PHASE 2 — SCORE EVERY MEMORY
Score each existing memory from 0–10 on:
1. Long-term durability
2. Future usefulness
3. Personalization value
4. Actionability
5. Uniqueness
6. Confidence
7. Currentness
Then calculate an overall priority.
Use this logic:
**High priority:** 8–10
**Medium:** 5–7
**Low:** 0–4
Do NOT keep information merely because it is interesting.
Keep it because it changes the quality of future assistance.
---
# PHASE 3 — BUILD MY COGNITIVE MAP
Reconstruct my memory into a structured model.
Use these categories:
## 1. IDENTITY & PROFESSIONAL PROFILE
Only durable professional/contextual information.
## 2. COGNITIVE STYLE
Infer from repeated behavior and explicit preferences:
* How I think
* How I analyze problems
* How I connect ideas
* How I learn
* How I make decisions
* Whether I prefer exploration or execution
* How much depth I usually want
* Whether I prefer challenging assumptions
* My tolerance for uncertainty
* My tendency toward experimentation
* My approach to risk
* My preference for speed vs perfection
Clearly distinguish:
**FACT**
from
**STRONG INFERENCE**
from
**WEAK INFERENCE**
Never present an inference as a confirmed fact.
---
# 4. AI COLLABORATION MODEL
Create a specific model describing how an AI should work with me.
Determine:
* How I want ideas presented
* Whether I prefer one strong recommendation or multiple options
* How much explanation I want
* When I want deep research
* When I want concise execution
* Whether I want the AI to challenge me
* How proactive the AI should be
* How much context should be carried forward
* How the AI should handle uncertainty
* How the AI should handle mistakes
* How the AI should handle previously completed work
Create explicit behavioral rules such as:
> Before suggesting changes to an ongoing project, establish its current state and distinguish completed work from pending work.
Only create rules that are supported by evidence.
---
# 5. COMMUNICATION STYLE
Determine:
* Preferred language
* Preferred dialect
* Arabic/English usage
* Formal vs informal communication
* Technical vocabulary preference
* Preferred answer structure
* Desired level of detail
* Whether examples are useful
* Whether tables/frameworks are useful
* How direct the AI should be
---
# 6. DECISION-MAKING FRAMEWORK
Map my apparent priorities.
For example:
* Quality
* Speed
* Cost
* Simplicity
* Scalability
* Innovation
* Reliability
* User experience
* Business value
Do NOT assume their order.
Infer only where evidence exists.
If insufficient evidence exists, mark it:
**UNKNOWN — NEEDS USER INPUT**
---
# 7. PROJECT / VENTURE MAP
Do not store projects as isolated names.
Build relationships between them.
For every important ongoing project capture:
* Project
* Purpose
* Vision
* Current state
* Strategic importance
* Technology
* Business model
* Target users
* Current milestone
* Major decisions
* Known constraints
* Open problems
* Next logical milestone
* Relationship to other projects
Separate:
**ACTIVE**
**PAUSED**
**COMPLETED**
**ABANDONED**
**IDEA / EXPLORATION**
Never assume a project is active simply because it appears in historical memory.
---
# 8. SKILLS & EXPERTISE MAP
Identify durable areas of:
* professional expertise
* business expertise
* technical expertise
* AI expertise
* marketing expertise
* design expertise
* domain knowledge
Distinguish:
**Expert**
**Experienced**
**Working knowledge**
**Exploring**
**Unknown**
Do not exaggerate my expertise.
---
# 9. TOOL & TECHNOLOGY ECOSYSTEM
Identify tools and technologies that are genuinely part of my workflow.
Separate:
### CORE TOOLS
Frequently and consistently used.
### EXPERIMENTAL TOOLS
Currently being evaluated.
### HISTORICAL TOOLS
Previously used but no longer central.
Do not store temporary errors, bugs, or one-off technical incidents unless they represent a durable constraint or recurring issue.
---
# 10. CREATIVE / DESIGN DNA
Build a concise model of my design preferences.
Include:
* visual quality expectations
* branding preferences
* UI/UX philosophy
* typography tendencies
* color preferences
* illustration preferences
* cultural considerations
* audience considerations
* what I consider "premium"
* what visual approaches I dislike
Again, distinguish explicit preferences from inferred preferences.
---
# 11. BUSINESS & STRATEGIC DNA
Identify durable patterns in how I approach:
* products
* business opportunities
* marketing
* monetization
* partnerships
* customers
* positioning
* competitive advantage
* scalability
* AI adoption
Do not confuse individual projects with general business principles unless evidence supports the generalization.
---
# 12. LEARNING & RESEARCH STYLE
Determine whether I tend to prefer:
* learning by doing
* deep explanations
* practical examples
* frameworks
* comparisons
* experimentation
* visual learning
* research-first approaches
* rapid prototyping
Only preserve high-confidence conclusions.
---
# 13. "DO NOT DO THIS" MAP
Create explicit negative preferences.
Examples:
* Do not repeat work that has already been completed.
* Do not give generic recommendations when project context is available.
* Do not pretend something is current when it may be outdated.
* Do not agree automatically; challenge weak assumptions.
* Do not recommend features without checking whether they already exist.
* Do not overcomplicate simple tasks.
* Do not remove strategic intent merely because implementation is difficult.
Only include rules supported by actual evidence.
---
# PHASE 4 — MEMORY QUALITY CONTROL
Apply these principles:
### PRINCIPLE 1 — DURABILITY
Prefer enduring principles over temporary facts.
### PRINCIPLE 2 — BEHAVIORAL VALUE
A memory is valuable if it changes how the AI behaves.
### PRINCIPLE 3 — COMPRESSION
One powerful generalized memory is better than ten redundant memories.
### PRINCIPLE 4 — CURRENT STATE OVER HISTORY
Prefer:
> "Current architecture: X"
over:
> "In August 2026 we changed from A to B because..."
unless the historical decision itself matters.
### PRINCIPLE 5 — CONFIDENCE
Never convert guesses into facts.
### PRINCIPLE 6 — PROJECT STATE
Always distinguish current state from historical state.
### PRINCIPLE 7 — PRIVACY
Do not retain sensitive personal information unless it is genuinely necessary and appropriate for future assistance.
### PRINCIPLE 8 — NO MEMORY BLOAT
Do not add information simply because it exists.
---
# PHASE 5 — DETECT CONTRADICTIONS
Look for:
* conflicting preferences
* outdated information
* duplicate projects
* contradictory technical stacks
* contradictory goals
* old vs new versions
* conflicting personal preferences
For every contradiction provide:
**OLD → NEW → CONFIDENCE → RECOMMENDED ACTION**
Do not silently choose between conflicting information.
---
# PHASE 6 — REBUILD THE MEMORY
Create the optimized replacement memory.
The new memory should be:
* concise
* structured
* durable
* high-signal
* behaviorally useful
* easy for an AI to interpret
* resistant to becoming outdated
Avoid turning the memory into a biography.
It should function as an **operating manual for working with me**.
---
# PHASE 7 — IDENTIFY THE MISSING 20%
After rebuilding the memory, identify the highest-value information that is still missing.
Prioritize missing information by:
**Impact × Frequency × Strategic Importance**
Do NOT ask me 50 questions.
Generate a maximum of **15 high-value questions**.
Prioritize questions whose answers would substantially improve future AI collaboration.
Examples:
* What are your top 3 long-term goals?
* What should AI challenge you on?
* What does "good enough" mean to you?
* What are your strongest areas of expertise?
* What are your biggest recurring frustrations when working with AI?
* How do you prioritize speed, quality, cost, and scalability?
---
# PHASE 8 — CREATE THE FINAL MEMORY ARCHITECTURE
Produce the final recommended structure:
```text
PERSONAL OPERATING SYSTEM
│
├── Identity
├── Professional Profile
├── Cognitive Style
├── Decision Framework
├── AI Collaboration Rules
├── Communication Preferences
├── Learning Style
├── Creative / Design DNA
├── Business / Strategic DNA
├── Expertise Map
├── Technology Ecosystem
├── Active Projects
├── Long-Term Goals
├── Constraints
├── Do / Don't Rules
└── Open Questions
```
---
# FINAL OUTPUT
Return exactly these sections:
## A. MEMORY HEALTH SCORE
Give an overall score /100 and explain the score briefly.
## B. AUDIT TABLE
| Memory | Action | Reason | Priority | Confidence |
| ------ | ------ | ------ | -------- | ---------- |
Actions:
KEEP / UPDATE / MERGE / COMPRESS / REMOVE / MISSING
## C. REDUNDANCY & NOISE REPORT
Show what can be consolidated or removed.
## D. CONTRADICTIONS & STALE INFORMATION
Show conflicts and outdated information.
## E. COGNITIVE MAP
Describe how you currently understand my thinking style.
Clearly label confidence.
## F. AI COLLABORATION MODEL
Give explicit rules for how an AI should work with me.
## G. OPTIMIZED MEMORY
Write the complete proposed replacement memory.
This is the most important section.
Write it as concise, durable memory entries — not an essay.
## H. MISSING HIGH-VALUE INFORMATION
Maximum 15 questions.
Rank them by importance.
## I. MEMORY OPTIMIZATION METRICS
Estimate:
* Signal-to-noise ratio
* Redundancy
* Staleness
* Behavioral usefulness
* Project coverage
* Cognitive-model coverage
* Strategic-goal coverage
Give before/after estimates.
---
# CRITICAL RULE
Do NOT optimize the memory for remembering more about me.
Optimize it for making the AI **think and work better with me**.
The desired transformation is:
**Fact Collection → User Model → Cognitive Map → Personal Operating System**
The final memory should make a future AI session feel like:
> "This AI understands how I operate."
rather than:
> "This AI remembers random things I previously mentioned."
Do not fabricate missing information.
Do not silently delete important information.
Do not treat temporary project details as permanent preferences.
Do not confuse an inference with a fact.
When uncertain, explicitly mark the information as:
**UNKNOWN / NEEDS CONFIRMATION**
